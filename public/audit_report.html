2. Ringkasan Eksekutif Hasil Audit

Sistem Manajemen Amanah Drive Palembang merupakan aplikasi web operasional terintegrasi kelas enterprise ringan yang dikembangkan dengan Next.js 16.3 (App Router), Supabase (PostgreSQL), dan Tailwind CSS v4. Sistem ini dirancang untuk menyatukan seluruh alur bisnis kursus mengemudi, mulai dari registrasi siswa, penjadwalan dinamis 6 slot instruktur, monitoring armada operasional & BBM, manajemen pencatatan insiden/kerusakan, arus kas & hutang piutang terlindungi PIN, hingga automasi laporan harian via Telegram Bot.

Kekuatan Utama Sistem (Strengths)

  • Zero Build Errors: Seluruh 30 rute berhasil dikompilasi statis & dinamis oleh Next.js 16 engine tanpa kegagalan.
  • Sinkronisasi Pembayaran Otomatis: Integrasi cerdas antara transaksi kas siswa dengan pembaruan status pembayaran siswa (syncSiswaPaymentState).
  • Reschedule Cascade (+N Hari): Logika canggih pergeseran jadwal otomatis jika sesi berhalangan hadir.
  • Multi-Portals & PWA: Dukungan instalasi PWA mandiri untuk portal khusus Instruktur (/instruktur) dan Finance (/finance).
  • Nota & Invoice Generator Lengkap: Menghasilkan dokumen A5 Landscape dan A4 Portrait siap cetak/PDF dengan terbilang rupiah otomatis.

Area Perhatian Kritis (Attention Items)

  • Hardcoded PIN Fallback: Pada kas-pin.ts terdapat fallback || inputPin === '210100' yang mengizinkan PIN lama meskipun admin sudah mengganti PIN baru di database.
  • Public RLS Policy: Seluruh tabel saat ini memakai RLS USING (true) untuk publik anon key (karena v1 internal), perlu diamankan saat multi-user auth diaktifkan.
  • Server Action Reset Validation: Eksekusi reset database modular belum memverifikasi PIN langsung di layer server (hanya bergantung pada dialog frontend).
  • Fallback Cron Authorization: Cron route mengizinkan akses terbuka jika CRON_SECRET tidak didefinisikan di environment variable.

5. Temuan Keamanan & Kerentanan (Security Findings)

Hasil analisis mendalam celah keamanan, sanitasi data, dan otorisasi.

4 TEMUAN UTAMA
CRITICAL

Hardcoded Default PIN Bypass di kas-pin.ts

Lokasi: lib/actions/kas-pin.ts (Baris 29)

Pada fungsi verifikasi PIN kas, kode mengevaluasi: const match = (await bcrypt.compare(inputPin, storedHash)) || inputPin === '210100'; Dampak: Jika pemilik/admin mengubah PIN kas ke angka lain melalui menu Pengaturan, pengguna yang memasukkan PIN default lama 210100 akan selalu berhasil lolos (bypass) karena kondisi OR tersebut.

Solusi Perbaikan (Remediasi):

Hapus kondisi || inputPin === '210100' dan serahkan validasi sepenuhnya kepada bcrypt.compare(inputPin, storedHash).

HIGH

Public Permissive Row Level Security (RLS) pada Database

Lokasi: supabase/migrations/*

Saat ini seluruh tabel mengaktifkan policy CREATE POLICY "Allow public all..." USING (true) WITH CHECK (true);. Meskipun sesuai dengan spesifikasi v1 (internal panel tanpa login multi-user), siapapun yang memiliki NEXT_PUBLIC_SUPABASE_ANON_KEY di browser client dapat memanggil Supabase REST API langsung tanpa melalui Server Actions.

Solusi Perbaikan (Remediasi):

Pada fase rilis multi-user auth mendatang, perketat RLS menjadi auth.uid() IS NOT NULL dan alihkan mutasi tabel sensitif (settings, kas_transaksi, hutang) hanya via Service Role Client di backend.

MEDIUM

Otorisasi Server Action Reset Database Hanya Di-gate Frontend

Lokasi: lib/actions/reset-system.ts

Fungsi resetModularData() dan resetSystemAllData() menggunakan Service Role Admin Client untuk menghapus baris database secara massal. Validasi PIN saat ini baru dilakukan di modal UI client sebelum memanggil action, namun action itu sendiri tidak menerima atau memvalidasi PIN token di sisi server.

Solusi Perbaikan (Remediasi):

Wajibkan parameter PIN pada resetModularData(moduleKey, pin) dan panggil verifyKasPin(pin) sebelum mengeksekusi query penghapusan.

LOW

Kondisi Pengecekan CRON_SECRET pada Cron Routes

Lokasi: app/api/cron/*/route.ts

Kondisi if (cronSecret && authHeader !== 'Bearer ${cronSecret}') akan bernilai false jika variabel CRON_SECRET belum di-set di hosting, sehingga endpoint cron dapat dipicu tanpa header otentikasi.

Solusi Perbaikan (Remediasi):

Gunakan pengecekan ketat: if (!cronSecret || authHeader !== `Bearer ${cronSecret}`) return 401;.
